# Navigation & Information Architecture / 导航与信息架构

**ID:** navigation-ia

## Purpose / 用途
Describe how pages, features, content and user journeys are organized and discovered. Separate information architecture from visual layout.

描述页面、功能、内容和用户旅程如何组织与发现。信息架构必须与视觉布局区分。

## Activation / 启用条件
Enable for multi-page products, dashboards, workspaces, nested navigation, route-driven applications, tabs or complex content hierarchies.

多页面产品、Dashboard、工作台、嵌套导航、路由应用、标签页或复杂内容层级均应启用。

## Analysis checklist / 分析清单
- Sitemap, page hierarchy, route structure and naming.
- Primary/secondary/contextual navigation.
- Active, current, expanded, collapsed and breadcrumb states.
- Tabs vs routes vs filters: define the semantic distinction.
- Deep links, back behavior, preserved context and mobile navigation.
- Search/command entry points and navigation keyboard access.

- 站点地图、页面层级、路由结构和命名。
- 主导航、次级导航和上下文导航。
- 当前、选中、展开、折叠和面包屑状态。
- 明确标签页、路由和筛选的语义区别。
- 深链接、返回行为、上下文保持和移动端导航。
- 搜索/命令入口和导航键盘访问。

## Output contract / 输出契约
Provide an IA tree, route-to-navigation mapping, active-state rules, responsive navigation behavior and unresolved route questions.

输出信息架构树、路由与导航映射、当前状态规则、响应式导航行为和待解决的路由问题。

## Boundaries / 维度边界
Navigation owns discoverability and movement between information spaces. Layout owns spatial placement and grid. Do not duplicate navigation visual styling in Layout.
