# A3.5 资源入库与扩充规范

## 当前范围
30 套候选组合预设，使用 8 个已有风格家族与 85 项候选资源。30 套并非 30 个独立风格体系；未新增外部组件代码，也未宣称候选资产完成视觉或授权验收。

## 入库流程
提交候选 → 来源及授权审查 → ID/version 唯一性 → schema 与参数校验 → 依赖与适配器检查 → 独立预览 → 三视口与交互验收 → 发布可用版本。拒绝静默覆盖；保留旧版本与迁移报告。外部资源默认仅登记参考信息，不执行脚本或复制付费内容。

## 风格方案字段
id、name、nameEn、tags、status、description、preset。preset 必须包含 20 维稳定版本引用、锁定项及覆盖参数。组合方案引用 registry，不重复维护 CSS。候选方案可通过统一解析器生成 13 节说明。

## 资源状态
candidate（候选）、reference（仅参考）、available（已审核可用）、deprecated（废弃）。available 要求实际浏览器验证、许可证确认及可追溯来源；未通过不得标为 available。

## 扩充策略
先完善资源参数与结构适配器，再扩大数量。目标 50 色板、20 字体搭配、20 布局、15 导航、30 背景、20 表面、30 特效、100 组件变体、30 动效；均为后续目标，不是现有库存。新增资源需要更新 catalog、registry、preset schema 与运行时 validator，结构新类型需要适配器。避免仅增加无渲染行为的名称。

## A3.6 验收
运行迁移及核心 Node 测试，检查全部 30 方案，验证 375/768/1440px、键盘、焦点、减少动态效果、导出往返、收藏、搜索、锁定、导入、控制台错误。记录真实浏览器截图与失败项。检查霓虹独立资产包与 registry 的参数差异并统一来源。当前仅完成纯 JS 生成检查，尚未进行浏览器验收。
