# UI Design Studio 现行产品需求

范围确认日期为 2026-11-25。实现和验证进度见 [需求与验收清单](需求与验收清单.md)。

## 用户与目标

首期服务于在 Windows 本地使用 UI Design Studio 的维护者。维护者通过 Codex 整理设计素材，并在 WebUI 中按类查找和查看效果。Codex 负责把输入整理成符合项目规范的条目，让浏览器展示的效果能够追溯到实际入库参数。

当前基线为 [Alpha 应用](../app/index.html)。已有风格库、资源浏览、设计组合器、组件实验室和 13 节风格说明。首期在现有应用上完成素材入库和独立预览。

## 首期使用流程

1. 维护者将素材交给 Codex。首批使用项目内置素材作为来源，各新增一项有可见变化的配色、背景和组件变体。
2. `design-resource-intake`（设计素材入库）Skill 按现有 20 维分类归类，并校验 [资源 Schema](../design-system/v2/resource.schema.json)、参数、ID 与版本。确认前展示名称、维度、来源、授权状态、预览方式，以及将写入的内容。
3. 维护者确认后，Codex 同步更新 [资源注册表](../design-system/v2/registry.json) 和 [目录索引](../design-system/v2/catalog.json)。重复提交同一条目保持原记录，同 ID 同版本的内容冲突或非法参数需给出原因。任何校验失败都要保留原有数据和有效索引。
4. 刷新 WebUI，按类别浏览或按名称、ID 查找素材。详情展示来源和审核状态，并提供与入库参数一致的独立预览。三项新素材也可加入现有组合器。

## 素材示例与审核

| 示例 | 预览及验收效果 |
| --- | --- |
| 商务蓝深色配色 `color.business-blue-deep` | 基于现有商务蓝新增候选项，能看到调整后的色板和示例文字 |
| 密网格背景 `background.grid-dense` | 基于现有网格新增候选项，画布以 16 px 间距显示网格 |
| 加粗描边按钮 `components.outline-bold` | 基于现有描边组件新增候选项，显示 2 px 描边，并可查看已有按钮状态 |

候选素材（`candidate`）可以浏览和预览。授权和实际浏览器验收均有记录后，才可标为已审核可用（`available`）。沿用「仅参考」和「已废弃」状态，保留原条目及其版本引用。详细规则见 [资源入库规范](design/resource-admission.md)。

## DESIGN.md 采集后的维度差距分析与人工确认

### 目标

采集目标网站或应用 UI 后，AI 必须主动检查设计资料是否足以形成完整、可实施的设计文档和预览，而不是仅根据已看到的页面直接生成最终规范。

### 标准流程

1. 采集页面、截图、源码、样式、组件及交互证据，并记录实际访问范围。
2. 对照现有 20 个标准维度、9 个 Core 语义域、16 个 Extended 章节和适用的 7 个 Extensions，逐项检查覆盖程度。
3. 同时检查产品信息架构、页面清单、核心用户流程、组件变体、交互状态、响应式、无障碍和工程约束。
4. 生成设计维度差距报告，明确已覆盖、部分覆盖、缺失、未知和冲突项；区分 Observed、Inferred、Proposed、Unknown。
5. AI 自行调查可由现有授权来源核实的问题；对无法核实或需要主观选择的项目，列出需用户补充的截图、页面、文件或决定。
6. 用户可以逐项确认、修改、拒绝、暂缓，也可以自行查阅后补充材料。AI 吸收补充证据并更新差距报告。
7. 只有用户明确确认的项目才能写入正式 DESIGN.md、规范化 Token、预设和 preview.html、preview-dark.html、application-preview.html。未确认项保留待处理状态。
8. 完成后重新检查维度覆盖、Token 一致性、三个预览和实际执行过的浏览器验证。

### 审核边界

- 不得新增第 21 个标准维度，不得擅自修改 20 个稳定 ID 或映射关系。
- 不得把推断或设计建议伪装成来源事实。
- 用户要求继续采集、补充截图或保持讨论，不等于批准写入。
- 部分确认只允许应用明确批准的差距 ID。
- 具体报告格式与执行契约见 [设计维度差距分析与人工确认规范](design/design-gap-analysis.md)。
